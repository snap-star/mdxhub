### Previous Features

- **Nested content routing**: Blog posts under `content/blog/**` and docs pages under `content/docs/**` both support nested folders. `index.mdx` inside a folder resolves to the parent folder slug.
- **Filename fallback matching**: Blog routes can resolve posts by their file name when the current route uses the plain filename slug.
- **Relative image resolution**: MDX image sources that use relative paths are resolved against the current content folder and the built content asset map.
- **`.md` + `.mdx` discovery**: Both Markdown and MDX content files are discovered automatically with Vite glob patterns.
- **Explicit post sorting**: Blog posts support an `order` field for manual sorting before default date-based sorting.
- **Improved author schema**: The author registry supports an extended set of social links and profile fields.
- **Custom home page** (`/`): A brand-themed landing page with hero, features showcase, component demos, and latest posts.
- **Rich MDX Components**: Badge (22+ colors, 40+ icons), Tooltip (CSS-based, accessible), Callout (5 variants), Tabs (2 variants), Accordion, CardGrid, Timeline, VideoEmbed, Mermaid, CodeSandbox, and more — globally available in MDX.
- **Image lightbox**: Click any image to open a full-screen viewer with zoom (25%–400%), rotate, and keyboard controls.
- **CodeSandbox component**: Live, editable code sandboxes using Sandpack — React, TypeScript, Vanilla JS, and Static HTML templates.
- **Featured posts**: Set `featured: true` in frontmatter to highlight posts in a Featured widget.
- **Series grouping**: Use `series` and `seriesOrder` frontmatter to group related posts with prev/next links and progress bars.
- **CC License badges**: Set `cc` field in frontmatter to auto-render a Creative Commons badge in the post footer.
- **Blog Sort & View Controls**: Sort by Recent or Date Posted, toggle Ascending/Descending, switch between Card and List views. Preferences persisted to localStorage.
- **Blog List View**: Horizontal list layout with 70/30 text-to-thumbnail split, segmented pill badges, and active hover indicators.
- **Newsletter subscribe card**: Premium subscription card with gradient design and animated success feedback, configured via `site.config.json`.
- **Persisted blog preferences**: Sort mode, sort order, and view mode saved to localStorage via Zustand persist.
- **Shared `useBlogPosts` Hook**: Centralized hook for sort/view/pagination logic across blog routes.
- **Draft system**: Set `draft: true` in frontmatter to exclude posts from the published feed.
- **Dev watch script**: `pnpm run dev:watch` auto-regenerates content-index, RSS, and sitemap on content file changes.
- **Lazy-loaded Disqus comments**: IntersectionObserver-based lazy loading — embed script loads only when user scrolls near comments.
- **Build orchestrator**: `scripts/build.mjs` serves as single entry point for all prebuild steps. `package.json` scripts use clean commands instead of long `&&` chains.
- **Consolidated vendor chunks**: Manual chunk splitting via `rollupOptions.output.manualChunks` in `vite.config.ts`.
- **Lazy-loaded heavy components**: `Mermaid` and `CodeSandbox` use `React.lazy()` — heavy deps download only when content uses them.
- **Build-time image optimization**: WebP and AVIF variants generated via Sharp.
- **Dual-theme syntax highlighting**: Shiki with Monokai (dark) and GitHub Light (light) themes, plus diff/highlight/focus transformers.

## 🚧 Project Limitations

Because this is a static, file-based content platform, there are some inherent tradeoffs:

1. **Client-side search scaling**: The search index is built in the browser from loaded content. Very large libraries may increase initial page load memory usage.
2. **Content is Git-based**: All posts and docs are managed as files in the repository. There is no CMS admin panel or database-backed content editor.
3. **No built-in auth or comments**: Comments and authentication need to be added using third-party services like Giscus, Disqus, Supabase, or similar.

## 🐛 Known Behavior Notes

- **Reading time fallback**: When `readingTime` is not provided in frontmatter, the site estimates reading time from the available content metadata. For exact control, set `readingTime` manually.
- **Author lookup**: If `author` in blog frontmatter does not match any `id` in `content/authors/authors.yaml`, the post still renders but author details are omitted.
- **Link updates after rename**: Renaming content files or folders changes the resulting slug. Update links in other pages when you move or rename a post or docs page.
- **Tags parser**: The custom YAML parser in `scripts/generate-content-index.cjs` handles both inline array (`tags: ["a", "b"]`) and indented list (`tags:\n  - a`) syntax. Fields that look like arrays but are quoted strings are safely interpreted as strings.
- **Sitemap served via explicit Vercel rewrites**: The `vercel.json` includes explicit pass-through rewrites for `sitemap.xml`, `robots.txt`, and `rss.xml` before the catch-all SPA rule — ensuring Google Search Console receives the correct content.
- **content-index.json regeneration**: After adding or modifying content, the content-index, RSS, and sitemap must be regenerated. Use `pnpm run build` or the `dev:watch` script during development.
- **Post fields are flat, not nested**: `PostIndexEntry` uses flat fields (`featured`, `series`, `cc`, etc.) rather than a nested `frontmatter` object. Use `post.featured`, not `post.frontmatter.featured`.
- **Content validation enforces required frontmatter fields**: Build-time validation checks for `title`, `date`, `author`, `category`, `tags`, and `description` on blog posts, and `title`, `section`, `order`, `description` on docs. Missing fields cause a build error with the file path and field name.
- **Environment validation at startup**: Zod schema validates all `VITE_*` env vars on module import. Invalid or missing required values throw an error with field details. Run with valid `.env.local` or rely on schema defaults.
