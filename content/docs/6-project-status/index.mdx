Welcome to the **Project Status** page. Here you'll find an up-to-date log of newly implemented features, project limitations, and known behavior notes for this MDX platform.

## ✨ Newly Implemented Features

### Latest Optimization

- **Removed 3 unused dependencies**: `cmdk`, `class-variance-authority`, and `gray-matter` were dropped from `package.json` — unused imports across all source files. Smaller bundle, fewer dependency audits.
- **Lazy-loaded heavy MDX components**: `Mermaid` diagrams and `CodeSandbox` live editors now use `React.lazy()` — their heavy dependencies (~270KB gzipped combined) only download when a content page actually uses them.
- **Consolidated vendor chunks**: Small runtime deps (`zustand`, `fuse.js`, `date-fns`, `clsx`, `tailwind-merge`) merged into a single `vendor-misc` chunk, reducing HTTP requests from 4 tiny chunks to 1.
- **Build orchestrator**: Created `scripts/build.mjs` — a single entry point for all prebuild steps. `package.json` scripts simplified from long `&&` chains to clean `node scripts/build.mjs [mode]` commands.
- **Simplified blogPrefsStore**: Removed versioned migration system that mapped old `'oldest'` → `'datePosted'` — Zustand's persist handles unknown keys gracefully.
- **Extracted `createStore` factory**: Deduplicated the 90%-identical module-level store pattern from `lightboxStore.ts` and `tocStore.ts` into `src/lib/createStore.ts`. fewer duplicated patterns.
- **Deleted unused sort functions**: `sortByDate` and `sortPosts` removed from `@/lib/utils` — confirmed zero imports. -18 lines.
- **Shared LoadingSkeleton component**: Three near-identical skeleton components (`PageSkeleton`, `BlogSkeleton`, `DocsSkeleton`) replaced with a shared `<LoadingSkeleton text="..." minHeight="..." />` component.
- **Stdlib reuse in PostCard**: Manual `description.slice(0, 120) + '…'` replaced with `truncate(description, 120)` from `@/lib/utils` — word-boundary-aware cutting.
- **Inlined private store method**: `_applyTheme` in `themeStore.ts` inlined into `setTheme`/`toggleTheme` and removed from the public interface. -5 lines.
- **Stopped keyboard listener re-registration**: Search command palette (`SearchCommand.tsx`) now uses `useRef(open)` so the `keydown` listener is registered once (`[]` deps) rather than re-registered on every open/close toggle.
- **Improved diff line detection**: `CodeBlock.tsx` now uses Shiki's `data-diff-add`/`data-diff-remove` data attributes instead of fragile className string parsing.

### Previous Features

- **Nested content routing**: Blog posts under `content/blog/**` and docs pages under `content/docs/**` both support nested folders. `index.mdx` inside a folder resolves to the parent folder slug.
- **Filename fallback matching**: Blog routes can resolve posts by their file name when the current route uses the plain filename slug.
- **Relative image resolution**: MDX image sources that use relative paths are resolved against the current content folder and the built content asset map.
- **`.md` + `.mdx` discovery**: Both Markdown and MDX content files are discovered automatically with the Vite glob patterns.
- **Explicit post sorting**: Blog posts now support an `order` field for manual sorting before default date-based sorting.
- **Improved author schema**: The author registry supports an extended set of social links and profile fields.
- **Custom home page** (`/`): A brand-themed landing page with animated gradient hero, stat counters, tech stack badges, features showcase, component demos, latest posts, decorative floating orbs, and parallax scroll effects with bidirectional fade animations.
- **Badge component**: Colorful inline pill component (`<Badge variant="tip" icon="check">Done</Badge>`) with 22+ colors, admonition variants, and 40+ icon names — globally available in MDX.
- **Tooltip component**: Accessible hover/focus tooltip (`<Tooltip content="...">text</Tooltip>`) using `@base-ui/react` primitives — globally available in MDX.
- **Image lightbox viewer**: Any image in MDX content is now clickable and opens a full-screen overlay with zoom, rotate, and keyboard navigation.
- **CodeSandbox component**: Live, editable code sandboxes using Sandpack — supports React, TypeScript, Vanilla JS, and Static HTML templates with external dependencies and console output.
- **Accordion component**: Expandable/collapsible sections with `bordered` and `ghost` variants, `allowMultiple` mode, keyboard navigation, and animated height transitions via Framer Motion.
- **CardGrid component**: Responsive card grid (1–4 columns) with icons, titles, descriptions, optional links, and rich content children — perfect for feature listings and landing pages.
- **Parallax scroll effects**: Hero section on the home page features multi-layer parallax with different scroll speeds, using `requestAnimationFrame` and passive scroll listeners.
- **Bidirectional fade animations**: All sections on the home page fade in when scrolling down and fade out when scrolling up, using Framer Motion's `useInView` with `once: false`.
- **Dedicated search page**: Full-page search at `/search` with grouped results, recent searches in localStorage, and Fuse.js integration.
- **Logo hover animation**: The navbar logo transitions from a document icon to a home icon on hover with smooth Framer Motion fade/scale transitions.
- **Featured posts**: Set `featured: true` in frontmatter to highlight posts in a Featured widget on the blog homepage.
- **Series grouping**: Use `series` and `seriesOrder` frontmatter fields to group related posts into navigable series with prev/next links and progress indicators.
- **CC License badges**: Set `cc` in frontmatter (e.g., `cc: "CC-BY-4.0"`) to automatically render a Creative Commons license badge in the post footer.
- **Inline YAML array parsing**: Tags can use inline array syntax (`tags: ["react", "mdx"]`) in addition to the indented list format. Both work correctly.
- **Dev watch script**: Run `npm run dev:watch` alongside the dev server to auto-regenerate `content-index.json`, RSS, and sitemap on every content file save — no full rebuild needed.
- **Lazy-loaded Disqus comments**: The Disqus comment section uses a lazy-loading pattern with `IntersectionObserver` — the embed script is only loaded when the user scrolls near the comments, keeping initial page load fast.
- **Blog Sort & View Controls**: Blog posts can now be sorted by Recent or Date Posted with Ascending/Descending toggle, and displayed as Cards or a new horizontal List view. Controls are synced across the main blog index, category pages, and tag pages.
- **Blog List View**: A new horizontal list layout for blog posts with a 70/30 text-to-thumbnail split, segmented pill metadata badges (category, tags, date, reading time, comments), an active hover indicator, and a dedicated chevron block for posts without cover images.
- **Persisted Blog Preferences**: Sort mode, sort order, and view mode preferences are saved to `localStorage` via Zustand's `persist` middleware. Settings survive page reloads and browser restarts under the `mdx-blog-prefs` storage key.
- **Timeline Component**: New `<Timeline>` and `<TimelineItem>` MDX components for creating chronological timelines with date labels, icons, and color variants (brand, success, warning, danger, info).
- **Shared `useBlogPosts` Hook**: Extracted duplicate sort/view/pagination logic from three blog route files into a single `useBlogPosts(posts)` hook in `src/hooks/`. Reduces code duplication and centralizes sorting, slicing, and reset behavior.
- **Featured Badge Redesign**: The featured post badge now uses a frosted glass style with a red flame icon. On hover, the background fills with solid red and text turns white — replacing the previous gradient and glow effects.
- **Soft Hover Fill on List Items**: The post list view's hover effect changed from a blue gradient vertical bar to a soft primary-tinted background fill that scales in from the left — matching the sidebar category hover pattern.
- **Newsletter Subscribe Card**: A premium subscription card (`<NewsletterSubscribe />`) rendered automatically in blog post footers with gradient design, email input, and animated success feedback.
- **Newsletter Configuration via site.config.json**: The newsletter endpoint is configured centrally in `site.config.json` under the `newsletter.actionUrl` field — no code changes needed.
- **Animated Subscription Success**: After submitting the newsletter form, a Framer Motion animated success state replaces the form with a green checkmark and the subscribed email address, plus a "Change email" reset option.

## 🚧 Project Limitations

Because this is a static, file-based content platform, there are some inherent tradeoffs:

1. **Client-side search scaling**: The Fuse.js index is built in the browser from loaded content. Very large libraries may increase initial page load memory usage.
2. **Content is Git-based**: All posts and docs are managed as files in the repository. There is no CMS admin panel or database-backed content editor.
3. **No built-in auth or comments**: Comments and authentication need to be added using third-party services like Giscus, Disqus, Supabase, or similar.

## 🐛 Known Behavior Notes

- **Reading time fallback**: When `readingTime` is not provided in frontmatter, the site estimates reading time from the available content metadata. For exact control, set `readingTime` manually.
- **Author lookup**: If `author` in blog frontmatter does not match any `id` in `content/authors/authors.yaml`, the post still renders but author details are omitted.
- **Link updates after rename**: Renaming content files or folders changes the resulting slug. Update links in other pages when you move or rename a post or docs page.
- **Tags parser**: The custom YAML parser in `scripts/generate-content-index.cjs` handles both inline array (`tags: ["a", "b"]`) and indented list (`tags:\n  - a`) syntax. However, the parser runs before the MDX processor — fields that look like arrays but are quoted strings (e.g., `title: "[something]"`) are safely interpreted as strings.
- **Sitemap served via explicit Vercel rewrites**: The `vercel.json` now includes explicit 1:1 pass-through rewrites for `sitemap.xml`, `robots.txt`, and `rss.xml` before the catch-all SPA rule. This ensures Google Search Console receives the correct XML/plain-text content instead of the SPA's `index.html` — a common SEO pitfall for client-rendered apps on Vercel.
- **Build script consolidated**: The `prebuild` lifecycle hook has been removed and all content-generation scripts (content-index, RSS, sitemap, image variants) now run directly inside the `build` script. This guarantees they execute regardless of whether Vercel triggers `npm run build` or uses framework detection to run `vite build` directly.
- **content-index.json regeneration**: After adding or modifying content, the content-index, RSS, and sitemap must be regenerated. Use the `dev:watch` script during development, or run `node scripts/generate-content-index.cjs` manually if you see missing posts, tags, or series data.
- **Post fields are flat, not nested**: `PostIndexEntry` uses flat fields (`featured`, `series`, `cc`, etc.) rather than a nested `frontmatter` object. All code accessing post properties should use `post.featured`, not `post.frontmatter.featured`.
